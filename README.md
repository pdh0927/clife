# clife

[English](README.en.md)

Claude Code 플랜 사용량 한도를 작은 링 게이지로 메뉴바에 보여주는 macOS 앱. 언제 5시간 한도가 꽉 찰지 몰라서 매번 확인하러 다니는 게 귀찮아서 만들었다.

Claude 앱 메뉴바 아이콘을 눌렀을 때 뜨는 사용량 팝업과 **같은 API를 같은 방식으로 호출한다.** 그래서 숫자가 그쪽과 항상 일치한다 — 5시간 한도, 주간·모든 모델, 주간·모델별(Fable 등)까지.

**Anthropic 공식 제품 아님.** 그냥 개인 사이드 프로젝트다. Anthropic과 아무 제휴 없고, "Claude"/"Claude Code"는 그쪽 이름을 그대로 쓴 것뿐 — 이 앱이 어디서 데이터를 읽어오는지 설명하려고 언급한 것.

**Claude Pro나 Max 구독이 있어야 뭔가 보인다.** 다른 플랜은 한도 항목 자체가 비어서 온다.

## 동작 원리

`GET https://api.anthropic.com/api/oauth/usage` 하나가 전부다. 응답의 `limits` 배열이 곧 드롭다운의 각 줄이다:

```json
{"limits":[
  {"kind":"session",      "group":"session","percent":17,"resets_at":"..."},
  {"kind":"weekly_all",   "group":"weekly", "percent":36,"resets_at":"..."},
  {"kind":"weekly_scoped","group":"weekly", "percent":39,"resets_at":"...",
   "scope":{"model":{"display_name":"Fable"}}}
]}
```

앱은 이 배열을 **그대로** 그린다. 항목을 두 개만 골라 쓰지 않기 때문에, Anthropic이 새 한도(모델별, 표면별 등)를 추가하면 코드를 안 고쳐도 그날 바로 같이 뜬다.

인증 토큰은 Claude Code가 로그인 키체인에 저장해둔 `Claude Code-credentials` 항목에서 읽는다. **읽기만 한다** — 토큰 갱신은 Claude Code에 맡긴다. 우리가 갱신해서 다시 써넣으면 동시에 같은 일을 하는 Claude Code 프로세스와 경합이 나고, 지는 쪽은 refresh token이 통째로 무효가 된다. 토큰은 만료 직전까지 메모리에 캐시한다 — `security` 프로세스를 띄우는 데 25ms가 드는데, 폴링할 때마다 낼 이유가 없다.

### 호출 빈도

**이 엔드포인트는 레이트 리밋이 빡세다.** 몇 초 안에 연달아 부르면 `429`에 `Retry-After: 296`이 붙고, 예산이 말라 있을 땐 **16초 간격 두 번**으로도 막힌다. 그러니 예산을 어디에 쓸지 골라야 한다.

우선순위는 명확하다. **사람이 보고 있으면 무조건 가져오고, 아끼는 건 아무도 안 볼 때다.**

| 시점 | 조건 |
|---|---|
| **메뉴바 영역에 마우스가 들어오면** | 0.3초 머물면 **즉시** (캐시·백오프 무시) |
| 드롭다운 열 때 | **즉시** (캐시·백오프 무시) |
| 새로 고침 메뉴 | **즉시** (캐시·백오프 무시) |
| 절전 복귀 | 즉시 |
| 타이머 (유휴) | 10분, 30초 내 캐시가 있으면 그걸 씀 |

온디맨드 요청에는 5초 바닥만 둔다. 마우스가 메뉴바를 들락거리면 초당 몇 번씩 경계를 넘는데 그건 질문이 아니라 마우스 이동이다. 진짜로 보는 행위는 5초보다 촘촘할 수 없으니, 실질적으로 **링을 보면 항상 새로 가져온다**.

백오프까지 무시하는 건 계산된 선택이다. 429는 30ms 만에 거절로 돌아오고, 계속 물어본다고 차단이 연장되지도 않는다(`Retry-After` 카운트다운은 재시도와 무관하게 흘러간다). 시도의 비용은 왕복 한 번이고, 시도하지 않는 비용은 읽으러 온 사람 앞에 묵은 숫자를 들이미는 것이다.

배경 폴링이 10분인 이유도 같다. 예산이 하나뿐이라 — 16초 간격 두 번이면 429가 난다 — 아무도 안 보는 틱에 그걸 쓰면, 정작 사람이 마우스를 올려서 나가는 요청이 거절당한다. 배경은 알림 임계값을 살려두는 역할만 한다.

프리페치 기준은 **아이콘 호버가 아니라 메뉴바 진입**이다. 사람들이 실제로 읽는 건 링이고, 링은 흘끗 보는 거지 조준하는 게 아니다 — 20pt짜리 과녁에 마우스가 올라오길 기다리면 대부분의 "봄"을 놓친다. 풀스크린 앱 아래에서는 더 분명하다. 메뉴바가 숨어 있다가 마우스를 화면 맨 위로 밀어야 나타나는데, **그 미는 동작이 곧 아이콘이 보이기 시작하는 순간**이다. 거기서 요청을 시작하면 메뉴바가 애니메이션으로 내려오는 동안 링이 이미 따라잡는다.

구현은 상태 아이템의 트래킹 영역이 아니라 전역 마우스 모니터다. 마우스 이동 모니터는 접근성 권한이 필요 없고, 무엇보다 **메뉴바(따라서 버튼)가 아직 숨어 있는 동안에도 동작해야 하는데** 그 버튼에 붙인 트래킹 영역으로는 불가능하다. 영역 진입은 엣지 트리거라, 마우스가 초당 100번 움직여도 재무장하지 않는다.

배경 폴링이 실패하면 물러난다. 429는 서버가 말한 `Retry-After`를 **하한선**으로 쓰고(실제로 `Retry-After: 0`을 주면서 계속 거절하는 경우가 있어서 그 숫자를 상한선으로 믿으면 30초마다 벽에 들이받게 된다), 거기에 30초 → 60 → 120 → 240 → 480 → 900초 백오프를 겹친다. 그 외 실패(네트워크, 5xx)는 폴링 간격에서 멈춘다. 쉬는 동안엔 드롭다운 하단에 `요청 제한 · 3분 후 재시도`처럼 언제 다시 시도할지 적어둔다. 이 백오프는 **배경 폴링에만** 적용된다 — 사람이 보러 온 요청은 위에 적은 대로 그냥 나간다.

한 번 호출에 0.3초, 그것도 거의 전부 TTFB다(연결은 URLSession이 재사용). 유휴 상태의 배경 비용은 시간당 6회 × 2.4KB ≈ **15KB/시간**.

### 왜 statusline 방식을 버렸나

v1은 `statusline.sh`에 스니펫을 심어 `~/.claude/usage-status.json`을 쓰게 하고, 앱은 그 파일만 감시했다. 파일 감시 자체는 잘 돌았는데 **데이터 출처가 틀렸다**:

- statusLine 훅 JSON의 `rate_limits`는 직전 API 응답의 잔상이라 실제 값과 1%p씩 어긋났다.
- 모델별 주간 한도는 훅 JSON에 아예 없었다 — 두 줄밖에 못 보여줬다.
- 대화형 Claude Code 세션이 프롬프트를 그릴 때만 갱신됐다. 터미널을 닫아두면 숫자가 그대로 얼어붙고, `claude -p`로 도는 크론 작업이 쓴 사용량은 영영 반영되지 않았다.
- 세션을 새로 시작하면 첫 응답 전까지 `rate_limits`가 통째로 비어서, 앱이 며칠 전 값을 아무 표시 없이 계속 보여줬다.

API를 직접 부르면 네 가지가 한꺼번에 사라진다. 그래서 `install.sh`와 `statusline-snippet.sh`는 없앴다 — 이제 statusline에 붙일 게 없다.

## 설치

```sh
git clone <this-repo> clife
cd clife
./setup.sh
```

빌드해서 `/Applications`에 넣고 실행까지 해준다. 처음 실행할 때 걸리는 게 두 개 있다:

1. **Gatekeeper 경고** — `/Applications`에서 앱을 우클릭 → 열기 → 열기, 한 번만. 아래 참고.
2. **키체인 접근 허용** — `Claude Code-credentials`를 읽어도 되냐고 물어본다. "항상 허용"을 고르면 다음부터 안 묻는다.

Swift 코드만 고쳤으면 `./build.sh`만 다시 돌려도 된다.

`/Applications`에 수동으로 설치/재설치하려면:

```sh
pkill -f Clife.app/Contents/MacOS/Clife 2>/dev/null
rm -r -f /Applications/Clife.app
ditto Clife.app /Applications/Clife.app   # cp -R 말고, 이유는 아래
open /Applications/Clife.app
```

여기서 `cp -R`은 쓰지 마라 — `/Applications/Clife.app`이 이미 있으면 그 안으로 중첩 복사가 돼서, 껍데기만 바뀐 것처럼 보이고 실제로는 업데이트가 하나도 안 된다. 직접 겪어봤다. `ditto`는 어떤 상황이든 제대로 처리한다.

### Gatekeeper 경고

앱은 로컬에서 서명은 되어있지만(애드혹, 혹은 Xcode에 무료 Apple Development 인증서가 있으면 그걸로) Apple 노터라이즈는 안 받았다. 그래서 처음 더블클릭하면 macOS가 거부한다. `/Applications`에서 앱을 우클릭 → 열기 → 열기, 한 번만 하면 된다. 그다음부턴 macOS가 기억해서 그냥 정상적으로 실행된다. 로그인 시 자동 실행도 포함해서.

### 키체인 프롬프트가 빌드할 때마다 뜨지 않는 이유

키체인 ACL 허용은 **코드서명 단위**로 기억된다. 이 앱은 애드혹 서명이라 `./build.sh`를 돌릴 때마다 서명이 바뀐다 — 앱 안에서 직접 `SecItemCopyMatching`을 불렀다면 빌드할 때마다 다시 물어봤을 거다. 그래서 토큰 읽기만 `/usr/bin/security`에 위임한다. Apple이 서명한 고정된 바이너리라 "항상 허용" 한 번이 재빌드를 넘어 유지된다.

## 제거

```sh
pkill -f Clife.app/Contents/MacOS/Clife
rm -r -f /Applications/Clife.app
```

앱이 남기는 건 `~/Library/Preferences/com.example.clife.plist`(표시 방식·위젯 상태·위젯 위치)와 `~/Library/Caches/com.example.clife/`(마지막 응답과 알림에 붙일 강아지 그림) 둘뿐이다. 지우려면 그 디렉터리째 지우면 된다. v1에서 올라왔다면 `~/.claude/statusline.sh`의 `# >>> clife` ~ `# <<< clife` 블록과 `~/.claude/usage-status.json`도 지워라 — 새 버전은 둘 다 안 쓴다.

## 표시 방식

드롭다운에 "아이콘으로 보기"와 "숫자로 보기"(예: `54%/29%`, 맨 처음 프로토타입이 이렇게 생겼었다) 둘 중 하나를 고를 수 있다. 고른 건 저장되고 다음 실행 때도 유지된다. 기본값은 아이콘.

## Raycast 단축키 (선택)

풀스크린 앱을 쓰고 있으면 메뉴바 자체가 안 보인다. `raycast/claude-usage.py`는 마우스를 위로 올리지 않고도 단축키 하나로 숫자를 띄운다:

```
5시간 29%  ·  주간 38%  ·  Fable 40%  ·  34분 후 초기화
```

설정: Raycast → Extensions → Scripts → **Add Script Directory** 에서 이 레포의 `raycast/` 폴더를 추가하고, "Claude 사용량"에 단축키를 지정한다. 표준 라이브러리만 쓰므로 `pip`도 `jq`도 필요 없다.

Raycast 스크립트를 한 곳에 모아두는 편이면, 등록은 그 폴더 하나만 하고 여기로 심링크를 걸면 된다 — 스크립트는 이 레포와 같이 버전 관리되고, Raycast는 경로 하나만 알면 된다:

```sh
ln -sf "$PWD/raycast/claude-usage.py" ~/workspace/raycast/claude-usage.py
```

단축키를 눌렀다는 건 "지금 알려줘"라는 뜻이라, 스크립트도 앱과 같은 규칙을 따른다 — **매번 새로 받아온다.** 5초 바닥은 연타 방지용일 뿐이다. 조회에 실패하면 마지막 값에 `334초 전 값 · 요청 제한`처럼 나이와 사유를 붙여서 보여준다.

캐시 파일(`~/Library/Caches/com.example.clife/usage.json`)은 **앱과 공유한다.** 단축키를 누르면 앱의 링도 같이 최신이 되고, 반대도 마찬가지다. 하나의 레이트 리밋을 나눠 쓰는데 따로 물어볼 이유가 없다. 양쪽 다 임시 파일에 쓰고 원자적으로 갈아끼우므로 반쪽짜리 파일을 읽는 일은 없다.

## 강아지

숫자만 보여주면 “지금 괜찮은가”는 매번 사람이 계산해야 한다. 서로 다른 창과 서로 다른 한도를 가진 퍼센트 세 개를 놓고 매번 같은 판단을 반복하게 되는 것이다. 그래서 **강아지가 트랙 위를 달린다** — 달린 거리가 사용량이고, 결승선이 한도다. 위치는 얼마나 썼는지를, 표정은 그게 걱정할 일인지를 말한다.

| 사용량 | 강아지 | 한마디 |
|---|---|---|
| ~50% | 네 다리가 다 뜬 전력질주, 귀가 날린다 | 아직 쌩쌩해요! |
| 50–70% | 보폭이 줄고 귀가 내려온다 | 반 넘게 달렸어요 |
| 70–90% | 혀를 내밀고 눈이 처진다 | 조금 지쳐가요… |
| 90%~ | 결승선 코앞에서 주저앉는다 | 잠깐 쉬어야 할 것 같아요 |

드롭다운 맨 위의 강아지는 **가장 먼저 막히는 한도** 하나만 대변한다. 세 마리를 세우면 어느 걸 봐야 하는지 다시 고민하게 되고, 그건 흘끗 보고 안다는 목적과 정반대다. 나머지 줄은 트랙 위 발자국으로 각자의 위치만 찍는다.

그림은 `design/dog/states.html` 의 SVG를 `src/dog.swift` 로 옮긴 것이다. 시안 쪽 도형을 원·타원·둥근 선·2차 곡선으로 제한해둔 덕에 `NSBezierPath` 에 1:1로 대응하고, 덕분에 둘이 조용히 갈라지지 않는다. 포팅 결과는 눈으로 확인해야 하므로 그 수단도 코드에 있다:

```sh
./Clife.app/Contents/MacOS/Clife --dogsheet /tmp/dog.png
```

4단계 × 스트라이드 6프레임과, 조립된 드롭다운 레이아웃을 PNG로 뽑는다. `NSMenuItem` 안의 커스텀 뷰는 실행 중에 캡처할 수 없어서 — 캡처하려는 순간 메뉴가 닫힌다 — 같은 뷰를 오프스크린으로 렌더하는 것이 실제로 조립된 결과를 보는 유일한 방법이다.

### 달리기

강아지는 실제로 달린다. 키프레임 두 장(뻗음/모음)을 이징으로 섞고, 몸통이 같이 튀고, 뒷발 뒤로 흙먼지가 피었다 사라진다. 스프라이트 시트를 들고 있지 않는 이유는 포즈를 손볼 때마다 맞춰줄 게 생기기 때문이다. 보폭 주기는 단계마다 달라서, 지친 강아지는 실제로 느리게 뛴다.

**보일 때만 돈다.** 메뉴의 강아지는 메뉴가 열려 있는 동안만, 위젯의 강아지는 위젯이 떠 있는 동안만. 닫히면 타이머가 사라지고 앱은 유휴 0%로 돌아간다.

값은 재봤다. 처음엔 코어 하나의 **3.6%** 였다 — 매 프레임 라벨까지 포함해 뷰 전체를 다시 그리고, 스무 개 남짓한 패스를 다시 스트로크하고 있었으니까. 세 가지를 고쳐 **1.0%** 가 됐다:

1. **강아지 사각형만 무효화** — 말풍선과 두 개의 텍스트 필드는 프레임마다 다시 그릴 이유가 없다
2. **한 스트라이드를 한 번만 래스터라이즈** — 그림은 주기마다 똑같으므로 이후로는 비트맵 붙이기다
3. **프레임율 상한 12fps** — 이 크기에서 그 위로는 배터리만 쓰고 더 부드러워 보이지 않는다

그중 애니메이션 자체가 차지하는 건 0.2%다(위젯을 띄워둔 상태 기준). 그래도 아까우면 드롭다운에서 **강아지 달리기**를 끄면 된다.

## 바탕화면 위젯

드롭다운 → **바탕화면 위젯**. 같은 강아지와 같은 한도가 바탕화면에 상주한다. 드래그로 옮기고 위치는 저장되며, 다음 실행에도 켜져 있던 상태로 돌아온다.

WidgetKit 익스텐션이 **아니다.** 그쪽은 별도 번들과 정식 프로비저닝, 노터라이즈된 부모 앱이 필요한데 이 프로젝트는 의도적으로 애드혹 서명이라(`build.sh` 참고) 서명 없는 위젯 익스텐션은 아예 로드되지 않는다. 데스크톱 윈도우 레벨에 고정한 테두리 없는 `NSPanel` 이면 같은 자리에 도달한다 — 바탕화면이 보일 때 보이고 무언가 덮으면 가려지는, 서명 이야기가 전혀 없는 방식으로.

내용은 드롭다운의 뷰를 **그대로 재사용**한다. 두 벌로 만들면 둘 중 하나를 고치는 순간부터 같은 숫자를 다르게 말하기 시작하고, 그건 위젯이 없느니만 못하다.

## 알림

각 한도가 30%, 50%, 60%, 70%, 80%, 90%, 95%를 넘을 때마다 데스크탑 알림이 한 번씩 뜬다. 같은 강아지가 같은 표정으로 전한다 — `주간 · Fable 50%` 한 줄만 던지면 그게 좋은 소식인지 나쁜 소식인지 이미 사라지는 배너 안에서 읽는 사람이 판단해야 하지만, 그림이 붙으면 글을 읽기 전에 톤이 먼저 도착한다. 같은 창(window) 안에서는 한 번만 울리고 창이 리셋되면 다시 울릴 수 있다. 앱을 켰을 때 이미 넘어있던 임계값은 조용히 통과시킨다 — 안 그러면 80%에서 앱을 처음 켰을 때 세 개가 한꺼번에 울릴 테니까.

## 왜 이렇게 생겼나

아이콘은 색깔 있는 이중 링이다 — 바깥쪽이 현재 5시간 세션, 안쪽이 주간. 주간 링은 여러 주간 한도 중 **가장 높은 값**을 쓴다. 평균이 아니라 제일 먼저 막히는 쪽이 실제로 당신을 멈춰 세우기 때문이다. 색은 statusline 컨텍스트 바와 같은 70%/90% 기준으로 초록/노랑/빨강. 실제 메뉴바 크기(20pt, 1배/2배, 라이트/다크)로 뽑은 이미지를 직접 눈으로 확인하고 정했는데, 그 작은 크기에서도 두 링이 충분히 구분됐다.

단색 템플릿 아이콘 대신 색을 쓴 이유는 서로 다른 기준으로 판단되는 두 값을 그 작은 크기에서 흑백 톤만으로 구분하긴 어려워서다. 대신 컬러 아이콘은 다크모드 자동 틴트를 못 받는다는 단점이 있는데, 이 정도면 괜찮은 맞바꿈이라고 생각한다. 어느 쪽이든 정확한 숫자는 링만 보고 짐작하게 하지 않는다 — 툴팁이랑 드롭다운에 항상 그대로 적혀 있다.

요청이 실패해도 마지막으로 받아온 숫자를 그대로 두고, 드롭다운 아래 상태줄에 왜 못 받았는지(`토큰 만료`, `연결 실패`, ...)와 `마지막 값 표시 중`을 같이 적는다. 폴링 한 번 실패했다고 화면을 비워버리면 5초짜리 와이파이 끊김이 로그아웃처럼 보인다. 마지막 성공 응답은 디스크에 남아서, 앱을 재시작해도 첫 요청이 나가기 전에 이미 링이 그려져 있다 — 쿨다운 중에 재시작했다고 1초 전까지 멀쩡하던 숫자를 버리고 물음표로 갈 이유가 없다. 한 번도 성공한 적이 **없을 때만** 물음표 아이콘이 뜬다 — "데이터 없음"이 "0% 사용"처럼 보이지 않게.

값이 15분 넘게 묵으면 **링에서 색이 빠진다.** 링의 존재 이유가 아무것도 열지 않고 흘끗 보고 판단하는 건데, 더 이상 최신이 아닌 숫자가 자신만만한 초록색으로 계속 앉아 있으면 그 판단이 틀린다. 회색은 "이게 내가 마지막으로 알던 값"이라고 사용자가 실제로 보고 있는 그 자리에서 말해준다. 이유는 드롭다운이 설명한다. 이 기준은 폴링 간격에 묶어두지 않았다 — "흘끗 보고 믿기엔 너무 묵었다"는 건 데이터의 성질이지, 우리가 얼마나 게으르게 폴링하는지의 함수가 아니다.

정확한 나이는 툴팁에도 적는다. 숫자에 나이가 안 붙어 있는 게 바로 묵은 값을 틀린 값처럼 보이게 만드는 원인이라서, "이거 지금 값 맞아?"의 답은 클릭이 아니라 호버로 얻게 해뒀다.

아이콘/제목을 새로 지정해도 macOS가 다시 그리는 걸 건너뛰는 경우가 있다(특히 화면이 절전에서 돌아온 직후, 또는 외장 모니터를 붙였다 뗐을 때). `needsDisplay`와 레이어 무효화를 둘 다 강제로 걸어서 데이터가 바뀌면 화면도 반드시 같이 바뀌게 해뒀다.

## 검증

```sh
./build.sh
./Clife.app/Contents/MacOS/Clife --selftest
```

실제 API 응답을 캡처해둔 페이로드로 파싱 경로를 확인한다 — 소수점 6자리 타임스탬프 처리, 필수 필드가 없는 행 버리기, 줄 제목 매핑, 리셋 문구. `assert`가 아니라 `precondition`을 쓰는데, `build.sh`가 `-O`로 빌드해서 `assert`는 통째로 제거되기 때문이다.

## 보안 관련

- OAuth 토큰은 **읽기만** 하고, 어디에도 저장하거나 로그로 남기지 않는다. 메모리에 있다가 `api.anthropic.com` 요청 헤더로만 나간다.
- 네트워크 목적지는 `api.anthropic.com/api/oauth/usage` 하나로 하드코딩돼 있다. 텔레메트리도, 분석도 없다.
- 이 저장소 어디에도 개인 경로, 사용자명, 팀 ID 같은 건 박혀있지 않다. 코드사이닝은 로컬에 있는 인증서를 아무거나 쓰고, 없으면 애드혹으로 넘어간다(`build.sh` 참고).
- 이건 공개 문서화된 API가 아니다. Anthropic이 언제든 바꾸거나 없앨 수 있고, 그러면 앱은 "응답 형식 오류"를 표시한다.
